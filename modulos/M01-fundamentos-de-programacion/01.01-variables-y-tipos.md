## 3. Explicación desde cero

### 3.1 Qué es una variable

Una **variable** es un espacio de memoria con tres cosas:

- Un **nombre**, con el que lo usas en el código (`edad`).
- Un **tipo**, que fija qué clase de dato puede guardar y cuánto espacio ocupa (`int`).
- Un **valor**, el dato que guarda ahora mismo (`29`).

```text
int edad = 29;
 │    │     └── valor inicial
 │    └──────── nombre
 └───────────── tipo
```

Tres operaciones:

| Operación | Sintaxis | Ejemplo |
|---|---|---|
| **Declarar** (crear) | `tipo nombre;` | `int edad;` |
| **Asignar** (dar o cambiar el valor) | `nombre = valor;` | `edad = 29;` |
| **Inicializar** (declarar y asignar) | `tipo nombre = valor;` | `int edad = 29;` |

El signo **`=` no significa "igual"**: significa **"guarda el valor de la derecha en la variable de la izquierda"**. Por eso `puntos = puntos + 5;` tiene sentido: calcula `puntos + 5` y lo guarda otra vez en `puntos`.

**Regla del compilador:** una variable local debe tener un valor asignado **antes** de leerse. Si no, `CS0165`.

### 3.2 C# es un lenguaje de tipado estático

Cada variable tiene un tipo **fijo** y el compilador lo comprueba **antes** de ejecutar. No puedes guardar un texto en una variable `int`: es un error de compilación, no un fallo en pleno uso. Es una ventaja: muchos errores se detectan antes de ejecutar.

### 3.3 Los tipos básicos

| Tipo | Qué guarda | Tamaño | Rango o precisión | Literal |
|---|---|---|---|---|
| `int` | Enteros | 32 bits | −2 147 483 648 a 2 147 483 647 | `42` |
| `long` | Enteros grandes | 64 bits | ±9,2 × 10¹⁸ (−9 223 372 036 854 775 808 a 9 223 372 036 854 775 807) | `42L`, `8_100_000_000L` |
| `double` | Decimales (punto flotante binario) | 64 bits | ≈ 15–17 dígitos significativos; hasta ≈ 10³⁰⁸ | `3.14`, `1.5e3` |
| `decimal` | Decimales exactos en base 10 | 128 bits | 28–29 dígitos significativos; hasta ≈ 7,9 × 10²⁸ | `12.50m` |
| `bool` | Verdadero o falso | — | `true` o `false` | `true` |
| `char` | **Un** carácter (UTF-16) | 16 bits | un carácter | `'M'` (comillas simples) |
| `string` | Texto (secuencia de caracteres) | variable | cualquier longitud razonable | `"Marta"` (comillas dobles) |

También existe `float` (32 bits, sufijo `f`), poco usado en este curso.

**Literales y sufijos.** Un número con punto decimal escrito sin sufijo es `double`. Para `decimal` necesita `m`; para `long`, `L`; para `float`, `f`. `'a'` es un `char`; `"a"` es un `string`: **no son lo mismo**. En los literales largos se pueden usar guiones bajos para legibilidad: `8_100_000_000L`.

### 3.4 `double` frente a `decimal`: por qué el dinero no usa `double`

Los ordenadores guardan los números en **binario**. Algunos decimales sencillos (como `0.1`) **no tienen representación exacta** en binario, igual que `1/3` no tiene representación decimal exacta (0,3333…). `double` guarda una **aproximación** y los errores pequeños se acumulan. `decimal` guarda los dígitos **en base 10**, así que `0.1m` es exactamente `0.1`.

| Usa… | Para… |
|---|---|
| `int` | Conteos, edades, cantidades, índices. |
| `long` | Enteros que superan los 2 mil millones (poblaciones, identificadores grandes, milisegundos). |
| `double` | Mediciones y cálculos científicos donde pequeñas diferencias de precisión no importan (alturas, temperaturas, promedios no monetarios). |
| `decimal` | **Dinero** y cualquier cantidad donde el cálculo en base 10 debe ser exacto. |
| `bool` | Respuestas sí/no, estados. |
| `char` | Un carácter suelto. |
| `string` | Texto, y **números con los que no calculas** (teléfono, DUI, código `A-1023`): no se suman ni se restan, y pueden empezar con ceros. |

### 3.5 `var`

`var` le pide al compilador que **deduzca el tipo** por el valor de la derecha. No es un tipo "flexible": `var x = 5;` es un `int` para siempre.

```text
var cantidad = 5;      // int
var precio = 5.0m;     // decimal
```

Úsalo cuando el tipo es obvio por la derecha. Cuando escribas el tipo, hazlo claro: aprenderás mejor y el código es más legible mientras aprendes.

### 3.6 Constantes

Una **constante** es un valor que **no cambia** nunca. Se declara con `const`, se le da el valor al declararla y el compilador impide reasignarla.

```text
const decimal Iva = 0.13m;
```

Convenciones de nombres de C# (seguiremos estas en todo el curso):

- **Variables locales:** `camelCase` (`totalAPagar`).
- **Constantes:** `PascalCase` (`Iva`, `MaxIntentos`).
- Nombres **descriptivos** (`precioUnitario`, no `p`).
- Solo letras, dígitos y `_`; **no pueden empezar por dígito** ni ser una palabra reservada.
- C# distingue mayúsculas y minúsculas: `Total` y `total` son nombres distintos.
- En este curso, **sin tildes ni `ñ`** en los identificadores (`anio`, `cantidadAnios`), aunque C# los permita.

### 3.7 Conversiones básicas

- **Implícita** (el compilador la hace solo porque no se pierde información): `int` → `long`, `int` → `double`, `int` → `decimal`.
- **Explícita** (tú lo pides con un *cast* porque se puede perder información): `(int)3.99` da `3` (se **trunca** la parte decimal, no se redondea).
- **No hay conversión** entre algunos tipos: `decimal` y `double` no se mezclan en una operación sin un cast explícito.
- **División entera:** `int` ÷ `int` da `int`. `7 / 2` es `3`. Para dividir con decimales, al menos uno de los operandos debe ser decimal (`7 / 2.0`).

El tema se amplía en 1.3 (operadores) y 1.4 (conversión y validación).

### 3.8 Mostrar valores: interpolación de cadenas

Hasta ahora has unido texto con `+`. Una forma más clara es la **interpolación**: un texto que empieza con `$` y lleva las expresiones entre llaves.

```text
Console.WriteLine($"Total: {total}");
```

Después de la expresión puedes poner `:` y un **formato**. `F2` significa *dos decimales fijos*: `{total:F2}` muestra `1234.50`. (El separador decimal depende de la configuración regional de tu equipo.)

## 4. Analogía intuitiva

- **Variables = cajas etiquetadas** con una forma fija. La etiqueta es el nombre; la forma es el tipo: en la caja de `int` solo caben enteros. Cambiar el contenido está permitido (`=`), cambiar la forma de la caja no.
- **`const` = una caja sellada:** una vez cerrada, no se abre.
- **`double` frente a `decimal` = medir con una cinta métrica frente a contar monedas.** La cinta mide casi todo, pero con un milímetro de error; las monedas se cuentan exactas. En dinero, el milímetro de error se acumula en pérdidas.

**Dónde falla:** una caja real no sabe nada de su contenido; las variables, en cambio, tienen un valor que el programa transforma en cada operación.

## 5. Ejemplos comentados

### Ejemplo 1 · Un dato de cada tipo

<!--v
modo: ejecuta
salida: siguiente
-->
```csharp
string nombre = "Marta";
char inicial = 'M';
int edad = 29;
double altura = 1.68;
decimal saldo = 1250.50m;
bool estudiando = true;

Console.WriteLine($"Nombre: {nombre}");
Console.WriteLine($"Inicial: {inicial}");
Console.WriteLine($"Edad: {edad}");
Console.WriteLine($"Altura: {altura} m");
Console.WriteLine($"Saldo: {saldo}");
Console.WriteLine($"Estudiando: {estudiando}");
```

```text
Nombre: Marta
Inicial: M
Edad: 29
Altura: 1.68 m
Saldo: 1250.50
Estudiando: True
```

Cada variable tiene el tipo que corresponde a su dato. Observa que `bool` se muestra como `True` (con mayúscula inicial) y que el `decimal` conserva sus dos decimales (`1250.50`).

### Ejemplo 2 · Reasignar una variable

<!--v
modo: ejecuta
salida: siguiente
-->
```csharp
int puntos = 10;
Console.WriteLine(puntos);

puntos = puntos + 5;
Console.WriteLine(puntos);

puntos = puntos * 2;
Console.WriteLine(puntos);
```

```text
10
15
30
```

`puntos = puntos + 5;` se lee: "toma el valor actual de `puntos`, súmale 5 y guarda el resultado en `puntos`".

### Ejemplo 3 · Los límites de `int` y `long`

<!--v
modo: ejecuta
salida: siguiente
-->
```csharp
Console.WriteLine(int.MinValue);
Console.WriteLine(int.MaxValue);
Console.WriteLine(long.MaxValue);
```

```text
-2147483648
2147483647
9223372036854775807
```

Cada tipo numérico tiene `MinValue` y `MaxValue`. Salirse de ese rango no da un error visible por defecto (ver Ejemplo 7).

### Ejemplo 4 · `double` frente a `decimal`

<!--v
modo: ejecuta
salida: siguiente
-->
```csharp
Console.WriteLine(0.1 + 0.2);
Console.WriteLine(0.1m + 0.2m);
Console.WriteLine(0.1 + 0.2 == 0.3);
Console.WriteLine(0.1m + 0.2m == 0.3m);
```

```text
0.30000000000000004
0.3
False
True
```

Con `double`, `0.1 + 0.2` **no es** exactamente `0.3`: la comparación da `False`. Con `decimal` sí lo es. Por eso **nunca se comparan `double` con `==`** esperando igualdad exacta, y por eso el dinero va en `decimal`.

### Ejemplo 5 · Constantes

<!--v
modo: ejecuta
salida: siguiente
-->
```csharp
const decimal Iva = 0.13m;
decimal precio = 100m;
decimal impuesto = precio * Iva;
Console.WriteLine($"Impuesto: {impuesto}");
```

```text
Impuesto: 13.00
```

El IVA es un valor fijo del programa: al llamarlo `Iva` el código se explica solo y, si cambia la ley, se corrige en **un único lugar**. Los números "mágicos" escritos sueltos (`precio * 0.13m`) obligan a buscar todas las apariciones.

### Ejemplo 6 · Interpolación y formato

<!--v
modo: ejecuta
salida: siguiente
-->
```csharp
decimal total = 1234.5m;
Console.WriteLine($"Total: {total}");
Console.WriteLine($"Total: {total:F2}");
```

```text
Total: 1234.5
Total: 1234.50
```

Sin formato se muestra el valor tal cual; con `F2`, siempre dos decimales.

### Ejemplo 7 · El desbordamiento silencioso

<!--v
modo: ejecuta
salida: siguiente
-->
```csharp
int cantidad = int.MaxValue;
cantidad = cantidad + 1;
Console.WriteLine(cantidad);

long grande = int.MaxValue;
grande = grande + 1;
Console.WriteLine(grande);
```

```text
-2147483648
2147483648
```

Al superar el máximo de `int`, el valor "da la vuelta" hasta el mínimo **sin avisar**. Con `long` cabe sin problema. Moraleja: si un dato puede superar ~2 mil millones, usa `long`.

### Ejemplo 8 · Conversiones

<!--v
modo: ejecuta
salida: siguiente
-->
```csharp
int entero = 7;
double comoDouble = entero;
double pi = 3.99;
int truncado = (int)pi;

Console.WriteLine(comoDouble);
Console.WriteLine(truncado);
Console.WriteLine(7 / 2);
Console.WriteLine((double)7 / 2);
```

```text
7
3
3
3.5
```

`int` → `double` es implícita: no se pierde nada. `double` → `int` exige `(int)` y **trunca**: `3.99` se vuelve `3`. `7 / 2` es división entera; `(double)7 / 2` convierte el 7 antes de dividir.

### Ejemplo 9 · Qué tipo tiene realmente cada cosa

<!--v
modo: ejecuta
salida: siguiente
-->
```csharp
var a = 5;
var b = 5.0;
var c = 5.0m;
var d = 'x';
var e = "x";
var f = 5L;
var g = true;

Console.WriteLine($"{a.GetType().Name} {b.GetType().Name} {c.GetType().Name} {d.GetType().Name} {e.GetType().Name} {f.GetType().Name} {g.GetType().Name}");
```

```text
Int32 Double Decimal Char String Int64 Boolean
```

`GetType().Name` devuelve el nombre del tipo real. `int` es un alias de `Int32`, `long` de `Int64`, `bool` de `Boolean`. Es una forma de **comprobar** el tipo de un literal en lugar de suponerlo.

## 6. Análisis del código

**Ejemplo 2 como traza.** Cada fila es el estado de la variable *después* de ejecutar la línea:

| Línea | Instrucción | `puntos` | Salida |
|---|---|---|---|
| 1 | `int puntos = 10;` | 10 | |
| 2 | `Console.WriteLine(puntos);` | 10 | `10` |
| 4 | `puntos = puntos + 5;` | 15 | |
| 5 | `Console.WriteLine(puntos);` | 15 | `15` |
| 7 | `puntos = puntos * 2;` | 30 | |
| 8 | `Console.WriteLine(puntos);` | 30 | `30` |

**Qué pasa con el desbordamiento (Ejemplo 7).** `int.MaxValue` es `0111 1111 …` en binario (32 bits). Sumarle 1 produce `1000 0000 …`, que en la representación de enteros con signo es el **mínimo**. No se produce excepción porque, por defecto, C# no comprueba el desbordamiento aritmético (existe `checked` para pedirlo; se verá más adelante).

**Qué pasa con `0.1 + 0.2` (Ejemplo 4).** En binario, `0.1` y `0.2` son fracciones periódicas que se cortan al tamaño del `double`; el resultado de sumarlos es el `double` más cercano a su suma, que **no coincide** con el `double` más cercano a `0.3`. `decimal` guarda `1` y `2` con "una cifra decimal" y suma exacto.

**Por qué `var` no es "magia" (Ejemplo 9).** El compilador decide el tipo **al compilar** y desde ahí todo funciona igual que si lo hubieras escrito tú.

## 7. Errores frecuentes

### Error 1 · Guardar un tipo en otro incompatible (`CS0029`)

<!--v
modo: error CS0029
-->
```csharp
int edad = "veinte";
```

`CS0029`: no se puede convertir `string` en `int`. **Corrección:** usar el tipo y el valor que corresponden (`string edad = "veinte";` o `int edad = 20;`).

### Error 2 · Perder decimales sin pedirlo (`CS0266`)

<!--v
modo: error CS0266
-->
```csharp
double altura = 1.75;
int alturaEntera = altura;
```

`CS0266`: no hay conversión implícita de `double` a `int` porque se perdería información. **Corrección:** `(int)altura` si de verdad quieres truncar, o cambiar el tipo de `alturaEntera`.

### Error 3 · Un literal con decimales sin sufijo para `decimal` (`CS0664`)

<!--v
modo: error CS0664
-->
```csharp
decimal precio = 9.99;
```

`9.99` es un `double`; para `decimal` hace falta la **`m`**: `9.99m`. Lo mismo ocurre con `float` y la `f` (`CS0664` también).

### Error 4 · Usar una variable sin valor (`CS0165`)

<!--v
modo: error CS0165
-->
```csharp
int x;
Console.WriteLine(x);
```

`CS0165`: la variable local no tiene valor asignado. **Corrección:** inicializarla (`int x = 0;`) o asignarle un valor antes de leerla.

### Error 5 · Reasignar una constante (`CS0131`)

<!--v
modo: error CS0131
-->
```csharp
const int Max = 10;
Max = 20;
```

`CS0131`: el lado izquierdo de una asignación debe ser una variable. Una constante no lo es. **Corrección:** declararla como variable si necesita cambiar.

### Error 6 · Declarar dos veces el mismo nombre (`CS0128`)

<!--v
modo: error CS0128
-->
```csharp
int a = 1;
int a = 2;
```

`CS0128`: el nombre ya está definido en este ámbito. **Corrección:** para cambiar el valor, **asignar** (`a = 2;`), no volver a declarar.

### Error 7 · Mezclar `decimal` con `double` o con `string` (`CS0019`)

<!--v
modo: error CS0019
-->
```csharp
decimal d = 5m;
double x = 2.5;
decimal r = d * x;
```

`CS0019`: el operador `*` no se puede aplicar a `decimal` y `double`. **Corrección:** usar un solo tipo (`2.5m`) o convertir de forma explícita si de verdad lo necesitas. El mismo código aparece con `decimal * string`.

### Error 8 · `char` frente a `string`

<!--v
modo: error CS0029
-->
```csharp
char c = "a";
```

Un `char` va entre **comillas simples** (`'a'`); un `string`, entre dobles (`"a"`). Son tipos distintos.

### Error 9 · Desbordamiento: en una constante, el compilador te avisa

<!--v
modo: error CS0220
-->
```csharp
int x = int.MaxValue + 1;
```

`CS0220`: la operación desborda en tiempo de compilación. Pero **con una variable** (Ejemplo 7) el desbordamiento ocurre **en silencio**: el compilador no puede saber el valor.

### Errores lógicos habituales

| Error | Qué ocurre | Corrección |
|---|---|---|
| `7 / 2` esperando 3.5 | Da `3` (división entera). | `7 / 2.0` o `(double)7 / 2`. |
| `0.1 + 0.2 == 0.3` con `double` | Da `False`. | Usar `decimal` si es dinero; para mediciones, comparar con una tolerancia (más adelante). |
| `"5" + "3"` | Da `"53"` (texto), no `8`. | Convertir a número antes de sumar (unidad 1.4). |
| Guardar un teléfono como `int` | Pierde ceros iniciales y no cabe un número largo. | `string`. |
| Usar `int` para una población mundial | Desbordamiento silencioso. | `long`. |

## 8. Variaciones

- **Si cambia el requisito de tamaño:** una edad cabe en `int`; la población de un país también; la mundial, no (usa `long`).
- **Si ahora el precio es en dólares y centavos:** `double` pasa a `decimal` y los literales a `m`.
- **Si necesitas más de un dato del mismo tipo:** se pueden declarar varios en una línea (`int a = 1, b = 2;`), pero una variable por línea se lee mejor.
- **Si ya no quieres que el valor cambie:** `const`.
- **Mostrar con otro formato:** `F0` (sin decimales), `F3` (tres) o, más adelante, formatos de moneda y de fecha según la cultura.
- **`var`:** `var total = 0m;` equivale a `decimal total = 0m;`.
