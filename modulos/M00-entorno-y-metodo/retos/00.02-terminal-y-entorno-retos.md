# Retos · 0.2 Terminal, archivos y carpetas; instalación y verificación del entorno

Lección: [00.02-terminal-y-entorno.md](../00.02-terminal-y-entorno.md) · Soluciones (**tras tres intentos documentados**): [soluciones](../../../soluciones/M00-entorno-y-metodo/00.02-terminal-y-entorno-soluciones.md)

**Cómo trabajar**

1. Tu carpeta de trabajo es `practica/` dentro de este repositorio. Todo lo que crees va dentro de `practica/semana-01/`.
2. Antes de cualquier comando que cree o borre algo: `pwd`.
3. Las pistas están plegadas: ábrelas una a una, solo tras intentar. Anota cuántas usaste.
4. Registra en tu bitácora los **comandos exactos** que ejecutaste y el resultado real.
5. Estos retos no tienen "salida de programa": se verifican mirando el estado de tu carpeta con `ls` (o `ls -Recurse` en PowerShell) y la salida de los comandos.

## Nivel 1 · Comprensión

### R-0.2-N1-A · ¿Dónde estoy?

**Enunciado.** Este es el árbol de un taller:

```text
C:\Taller
├── codigo
│   ├── clase1
│   └── clase2
│       └── ejemplos
├── datos
└── docs
    └── manuales
```

Empiezas en `C:\Taller\codigo`. Ejecutas, en orden, estos comandos. Después de **cada uno**, escribe el directorio actual (o `ERROR` si el comando falla):

1. `cd clase2`
2. `cd ejemplos`
3. `cd ..\..\..\datos`
4. `cd ..\docs\manuales`
5. `cd ..`
6. `cd C:\Taller\codigo\clase1`
7. `cd .`
8. `cd ..\clase2\..\clase1`

Pregunta extra: ¿qué pasaría si el comando 3 fuera `cd ..\..\datos`?

**Cómo verificarlo.** Si quieres, construye ese árbol en tu carpeta de práctica y compruébalo. Predice primero.
**Criterio.** Los ocho directorios correctos y la pregunta extra razonada.

### R-0.2-N1-B · Rutas absolutas y relativas

**Enunciado.** Con el mismo árbol:

1. Escribe la ruta **relativa** que lleva de `C:\Taller\docs\manuales` a `C:\Taller\codigo\clase2\ejemplos`.
2. Escribe la ruta **absoluta** de la carpeta `datos`.
3. Desde `C:\Taller\datos`, escribe la ruta relativa a `C:\Taller\docs`.
4. Estando en `C:\Taller\datos`, ¿es válido `cd codigo`? ¿Por qué?
5. ¿Cuántos `..` hacen falta para ir de `C:\Taller\codigo\clase2\ejemplos` a `C:\Taller`?

**Criterio.** Cinco respuestas correctas con la razón de la 4.

### R-0.2-N1-C · Leer salidas de verificación

**Enunciado.** Para cada situación di: ¿está todo bien o hay un problema? Si hay problema, **cuál es la causa más probable** y **qué haces primero**.

| N.º | Comando | Lo que se ve |
|---|---|---|
| 1 | `dotnet --version` | `8.0.404` |
| 2 | `dotnet --list-sdks` | *(no muestra nada)* y `dotnet new console` responde `No .NET SDKs were found.` |
| 3 | `git --version` | `git : El término 'git' no se reconoce como nombre de un cmdlet, función, archivo de script o programa ejecutable.` |
| 4 | `dotnet --version` | `10.0.100` |
| 5 | `dotnet run` | `Couldn't find a project to run. Ensure a project exists in …\semana-01…` |
| 6 | Conectar con SSMS a un servidor local de desarrollo | `…error: 0 - The certificate chain was issued by an authority that is not trusted.` |

**Criterio.** 5 de 6 diagnósticos razonables y una primera acción concreta (un comando o un paso) para cada uno.

## Nivel 2 · Aplicación

### R-0.2-N2-A · Estructura de carpetas solo con comandos

**Enunciado y contexto.** Vas a preparar tu espacio para la semana 1 sin usar el ratón.

**Requisitos funcionales.** Dentro de `practica/semana-01/` crea exactamente esta estructura, usando **solo comandos**:

```text
semana-01
├── 00-01-fuente
├── 00-02-entorno
│   ├── capturas
│   └── versiones
├── 00-03-proyecto
└── notas
    └── bitacora-semana-01.md
```

**Restricciones técnicas.** Sin el Explorador. Nombres exactos (sin tildes, sin espacios). `bitacora-semana-01.md` puede estar vacío.

**Entradas y salidas esperadas.** Sin entrada. El resultado es el árbol anterior.

**Ejemplo de verificación.** `ls -Recurse` (PowerShell) o `ls -R` (bash) debe mostrar esas carpetas y ese archivo, ninguna más.

**Casos límite.** (1) Ejecuta de nuevo uno de los comandos `mkdir`: ¿qué responde? ¿Por qué? (2) ¿Qué pasa si te olvidas de hacer `cd` antes de `mkdir` y estabas en otra carpeta? Anota dónde se habría creado.

**Pistas progresivas**
<details><summary>Pista 1 · concepto</summary>Cada <code>mkdir</code> crea dentro del directorio donde estás en ese momento.</details>
<details><summary>Pista 2 · método</summary>Escribe primero la lista de comandos en tu bitácora, en orden, indicando después de cada uno el directorio actual (como en la traza de la lección).</details>
<details><summary>Pista 3 · localización</summary>Un archivo vacío no se crea con <code>mkdir</code>. Revisa la tabla de comandos de la sección 3.3.</details>

**Pruebas.** `ls -Recurse` coincide con el árbol · el archivo existe · no hay carpetas sobrantes · registraste los comandos.

**Criterios** (rúbrica A): funcional 35 · razonamiento 20 (lista de comandos pensada antes) · calidad 15 (orden lógico, sin comandos repetidos) · límites 15 (los dos casos límite) · pruebas/explicación 15.

**Errores frecuentes.** Crear `00-02-entorno` en la carpeta equivocada; olvidar `cd ..` y anidar de más; usar tildes o espacios en los nombres.

### R-0.2-N2-B · La ficha de entorno

**Enunciado y contexto.** Documenta tu entorno **real** (no el ideal) para saber cómo estás y qué falta.

**Requisitos funcionales.** Crea `practica/semana-01/00-02-entorno/ficha-de-entorno.md` con estos campos, todos con datos que hayas obtenido tú **ejecutando comandos o abriendo las herramientas**:

| Campo | Cómo se obtiene |
|---|---|
| Fecha | La de hoy |
| Sistema operativo y versión | Configuración del sistema |
| Terminal que usas | La que abriste |
| Resultado de `dotnet --version` | El comando |
| Resultado de `dotnet --list-sdks` | El comando |
| Resultado de `git --version` | El comando |
| Editor y versión | *Acerca de* en el editor |
| Versión de SQL Server | `SELECT @@VERSION;` |
| Herramienta SQL y versión | *Acerca de* |
| Ruta de tu carpeta de trabajo | `pwd` dentro de `practica/` |
| Pendientes | Qué no está instalado o no funciona |

**Restricciones técnicas.** Nada inventado. Si algo no está instalado, escribe `pendiente` y qué harás.

**Entradas y salidas esperadas.** Un archivo Markdown con los campos rellenos.

**Casos límite.** Si tu SQL Server está en otra máquina o en un contenedor, anótalo; si usas una versión distinta de la recomendada, anótalo también y di si crees que afecta.

**Pistas progresivas**
<details><summary>Pista 1 · concepto</summary>La utilidad de la ficha es que otra persona (o tú dentro de dos meses) pueda reproducir tu entorno.</details>
<details><summary>Pista 2 · método</summary>Para pegar la salida exacta de un comando, cópiala de la terminal en vez de escribirla.</details>

**Pruebas.** Todos los campos tienen valor o `pendiente`; las versiones coinciden con lo que muestra tu terminal ahora.

**Criterios.** Funcional 35 (campos completos y reales) · razonamiento 20 (pendientes con plan) · calidad 15 · límites 15 (anotaste las excepciones) · pruebas/explicación 15 (puedes explicar qué hace cada comando).

**Errores frecuentes.** Escribir versiones de memoria; poner `10` sin el número completo; omitir los pendientes.

## Nivel 3 · Resolución independiente

### R-0.2-N3-A · Prueba de humo sin guía

**Enunciado y contexto.** Demuestra que tu entorno funciona de verdad: crear, ejecutar y modificar un programa solo con la terminal.

**Requisitos funcionales**
1. En `practica/semana-01/00-03-proyecto/` crea un proyecto de consola llamado `Presentacion`.
2. Haz que muestre tres líneas: tu nombre, `Estoy aprendiendo C#` y la fecha de hoy (escrita en el código).
3. Ejecútalo desde la terminal.
4. Cambia una de las líneas y vuelve a ejecutar.
5. Documenta los comandos usados y los resultados reales.

**Restricciones técnicas.** Sin mirar los ejemplos de la lección (consulta solo `dotnet new --help` o la documentación oficial si te atascas). Sin IA. Nombres sin tildes ni espacios (el contenido del texto sí puede tener tildes).

**Entradas y salidas esperadas.** Sin entrada. Salida de ejemplo:

```text
Ana Perez
Estoy aprendiendo C#
2026-10-14
```

**Casos límite.** (1) Ejecuta `dotnet run` desde la carpeta equivocada y anota el mensaje. (2) Mira qué carpetas aparecieron tras ejecutar (`bin`, `obj`): anota qué crees que contienen. (3) Cierra la terminal y vuelve a abrirla: ¿recuerdas cómo regresar a tu proyecto con un solo `cd` absoluto?

**Pistas progresivas**
<details><summary>Pista 1 · concepto</summary>Hay un comando que crea el proyecto y otro que lo ejecuta. Ambos dependen de dónde estás.</details>
<details><summary>Pista 2 · método</summary>Usa <code>dotnet new --help</code> para ver las opciones y <code>dotnet new list</code> para ver las plantillas; busca la de aplicación de consola.</details>
<details><summary>Pista 3 · localización</summary>El texto que se muestra está en <code>Program.cs</code>. Ábrelo con tu editor.</details>

**Pruebas**

| N.º | Prueba | Resultado esperado |
|---|---|---|
| 1 | `dotnet run` dentro de `Presentacion` | Tres líneas |
| 2 | Cambia la línea 2 y vuelve a ejecutar | La línea 2 cambia, las otras no |
| 3 | `dotnet run` desde `00-03-proyecto` (carpeta superior) | Mensaje de error de proyecto no encontrado |

**Criterios** (rúbrica A): funcional 35 · razonamiento 20 · calidad 15 (nombres, orden) · límites 15 (los tres casos límite documentados) · pruebas/explicación 15.

**Errores frecuentes.** Crear el proyecto fuera de `00-03-proyecto`; confundir `Presentacion` (nombre del proyecto) con el nombre de la carpeta; ejecutar sin entrar en la carpeta.

### R-0.2-N3-B · Diagnóstico de tres entornos rotos

**Enunciado y contexto.** Tres compañeros te piden ayuda. Para cada uno no basta con "reinstala": debes razonar como técnico.

1. *"Instalé el SDK ayer. Hoy abro PowerShell y `dotnet` no se reconoce, aunque el instalador terminó bien."*
2. *"`dotnet --version` muestra `9.0.300` aunque instalé el SDK de .NET 10."*
3. *"Creé un proyecto con `dotnet new console -n Hola`. Veo la carpeta `Hola` en el Explorador, pero `dotnet run` dice que no encuentra un proyecto."*

**Requisitos funcionales.** Para cada caso entrega: (a) **al menos tres hipótesis** ordenadas de más a menos probable, (b) el **comando o paso** que comprobaría cada una, (c) el **resultado que esperarías** si la hipótesis fuera cierta, y (d) la **solución** de la más probable.

**Restricciones técnicas.** Una hipótesis por línea; cada comprobación debe ser una acción concreta (comando o abrir una pantalla), no "revisar la instalación".

**Entradas y salidas esperadas.** Un documento con una tabla por caso.

**Casos límite.** ¿Qué harías si tras tu solución el problema persiste? Escribe un cuarto paso por caso.

**Pistas progresivas**
<details><summary>Pista 1 · concepto</summary>Pregunta primero qué cambió respecto a la última vez que funcionaba.</details>
<details><summary>Pista 2 · método</summary>Separa "¿está instalado?" de "¿la terminal lo encuentra?" y de "¿cuál versión usa?".</details>

**Pruebas.** Un compañero o el instructor debe poder seguir tus pasos sin que le expliques nada.

**Criterios.** Funcional 35 (hipótesis y soluciones correctas) · razonamiento 20 (orden por probabilidad) · calidad 15 · límites 15 (el cuarto paso) · pruebas/explicación 15.

**Errores frecuentes.** Proponer "reinstalar todo" como primer paso; hipótesis sin comprobación asociada; no distinguir SDK de runtime.

## Nivel 4 · Integración y transferencia

### R-0.2-N4-A · El proyecto perdido

**Enunciado y contexto.** Creaste un proyecto en una carpeta profunda y no recuerdas dónde. Tu trabajo es encontrarlo con comandos, reubicarlo y comprobar que sigue funcionando.

**Preparación.** Ejecuta (desde `practica/`):

```text
mkdir zona-caos
mkdir zona-caos\uno
mkdir zona-caos\uno\dos
cd zona-caos\uno\dos
dotnet new console -n Perdido
cd Perdido
dotnet run
cd C:\...\practica
```
(La última línea es solo recordarte que vuelvas a `practica/`: usa la ruta de tu equipo.)

**Requisitos funcionales**
1. **Encuentra** el proyecto usando un **comando de búsqueda** (no el Explorador). Anota el comando.
2. **Muévelo** a `practica/semana-01/00-04-perdido`.
3. Comprueba que `dotnet run` funciona desde la nueva ubicación.
4. **Limpia** lo sobrante (`zona-caos`) **solo después** de verificar que no queda nada dentro que importe.
5. Ejecuta el proyecto **desde una carpeta distinta** a la suya, indicando su ruta.

**Restricciones técnicas.** Sin ratón. Para borrar, primero `ls -Recurse` y lee. En PowerShell: `Remove-Item -Recurse zona-caos` (no `rm -rf`).

**Entradas y salidas esperadas.** Sin entrada. Resultado: el proyecto en `semana-01/00-04-perdido`, `dotnet run` muestra `Hello, World!`, y `zona-caos` ya no existe.

**Casos límite.** (1) ¿Qué pasa si borras `zona-caos` **antes** de mover el proyecto? (Piénsalo; no lo hagas.) (2) Mueve el proyecto *antes* y *después* de haberlo ejecutado una vez: ¿cambia algo? (3) ¿Qué pasa si ya existe `00-04-perdido`?

**Pistas progresivas**
<details><summary>Pista 1 · concepto</summary>Un proyecto de .NET se reconoce por un archivo con extensión <code>.csproj</code>.</details>
<details><summary>Pista 2 · método</summary>PowerShell: <code>Get-ChildItem -Recurse -Filter *.csproj</code> (alias <code>ls -Recurse</code>). bash: <code>find . -name "*.csproj"</code>.</details>
<details><summary>Pista 3 · localización</summary>Para ejecutar desde fuera de la carpeta del proyecto, <code>dotnet run</code> acepta la opción <code>--project</code> con una ruta.</details>

**Pruebas**

| N.º | Prueba | Resultado esperado |
|---|---|---|
| 1 | Comando de búsqueda | Muestra la ruta de `Perdido.csproj` |
| 2 | `ls` de `semana-01` | Aparece `00-04-perdido` |
| 3 | `dotnet run` en `00-04-perdido` | `Hello, World!` |
| 4 | `ls` de `practica` | Ya no aparece `zona-caos` |
| 5 | `dotnet run --project <ruta>` desde otra carpeta | `Hello, World!` |

**Criterios.** Funcional 35 · razonamiento 20 (orden: buscar → mover → verificar → limpiar) · calidad 15 (comandos mínimos) · límites 15 (los tres casos) · pruebas/explicación 15 (explicas por qué se verifica antes de borrar).

**Errores frecuentes.** Borrar antes de mover; mover solo `Program.cs` y no la carpeta del proyecto; escribir una ruta con espacios sin comillas.
