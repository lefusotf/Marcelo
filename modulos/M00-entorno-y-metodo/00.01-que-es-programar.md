## 3. Explicación desde cero

### 3.1 Algoritmo y programa

Un **algoritmo** es una secuencia **finita** de pasos **ordenados** y **sin ambigüedad** que resuelve un problema. "Sumar tres notas y dividir entre tres" es un algoritmo. "Haz algo con las notas" no lo es.

Un **programa** es un algoritmo escrito en un **lenguaje de programación** que una computadora puede ejecutar. Programar es escribir esas instrucciones con tanta precisión que una máquina sin sentido común las ejecute exactamente como pensabas.

Idea clave que usaremos todo el curso: **una computadora hace exactamente lo que escribes, no lo que querías decir.**

### 3.2 Entradas, proceso y salidas

Casi todo programa se puede describir así:

```text
ENTRADA (datos)  →  PROCESO (instrucciones)  →  SALIDA (resultado)
```

En un programa de promedio: entrada = tres notas; proceso = sumar y dividir; salida = el promedio. Cuando no sepas por dónde empezar con un problema, responde primero: *¿qué entra, qué se hace, qué sale?*

### 3.3 Del texto que escribes al programa que corre

El procesador de una computadora solo entiende **instrucciones de máquina** (números). Nadie escribe programas así. Por eso existe un recorrido de traducción. En .NET es este:

```text
Program.cs ──(compilador)──► App.dll (lenguaje intermedio, IL) ──(CLR + JIT)──► código de máquina ──► resultado
código fuente    COMPILAR         ensamblado                        EJECUTAR           CPU
```

1. **Código fuente.** El texto que escribes (`Program.cs`). Es solo texto: se puede abrir con cualquier editor.
2. **Compilación.** El **compilador** (en .NET se llama *Roslyn*) lee tu código, **comprueba que cumple las reglas del lenguaje** (sintaxis y tipos) y, si todo está bien, lo traduce a **IL** (*Intermediate Language*, lenguaje intermedio), que guarda en un archivo llamado **ensamblado** (`.dll`). Si algo incumple las reglas, el compilador **se detiene y te da errores**: no hay programa.
3. **Ejecución.** El **CLR** (*Common Language Runtime*, el motor de ejecución de .NET) carga el ensamblado. Un compilador **JIT** (*just-in-time*) traduce el IL a **código de máquina** mientras el programa corre, método por método, la primera vez que se usa. Entonces la CPU ejecuta el resultado.

> En la práctica .NET añade optimizaciones (por niveles, compilación previa parcial…). No las necesitas todavía; el modelo de arriba es correcto para razonar.

**SDK y runtime.** El **SDK** (*Software Development Kit*) son las herramientas para **desarrollar**: compilador, la herramienta de línea de comandos `dotnet`, plantillas de proyecto y el runtime. El **runtime** es lo mínimo para **ejecutar** programas ya compilados. Quien desarrolla instala el SDK; quien solo usa el programa necesita el runtime.

### 3.4 Tres momentos, tres tipos de error

Un problema puede aparecer en tres momentos distintos. Distinguirlos es la habilidad de depuración más importante:

| Momento | Tipo de error | ¿Hay programa? | Quién lo detecta | Ejemplo |
|---|---|---|---|---|
| Al **compilar** | De **compilación** (sintaxis, tipos, nombres) | **No** se genera | El compilador | Falta un `;` |
| Al **ejecutar** | De **ejecución** (excepción) | Sí, pero **se cae** | El runtime | Dividir un entero entre cero |
| Después, al **mirar el resultado** | **Lógico** | Sí, corre sin quejarse | **Tú** | Sumar en vez de multiplicar |

El error lógico es el más peligroso: **nadie te avisa**. Por eso se aprende a predecir resultados y a probar con casos conocidos.

### 3.5 El programa más pequeño

En C# moderno un programa puede ser una sola línea:

<!--v
modo: ejecuta
salida: siguiente
-->
```csharp
Console.WriteLine("Hola, mundo");
```

```text
Hola, mundo
```

Pieza por pieza:

- `Console` es una **clase** de la biblioteca de .NET (ya disponible: no hace falta importarla en un proyecto nuevo).
- `.` accede a algo que `Console` ofrece.
- `WriteLine` es un **método** (una acción con nombre): escribe en la consola y salta de línea.
- `( ... )` lleva los **datos** que se le pasan al método.
- `"Hola, mundo"` es un **literal de texto** (una cadena entre comillas dobles).
- `;` **termina** la instrucción.

C# distingue mayúsculas de minúsculas: `Console` no es `console`. Que el programa no tenga un `Main` visible se llama *sentencias de nivel superior* (*top-level statements*): el compilador genera el punto de entrada por ti.

## 4. Analogía intuitiva

Piensa en una **receta de cocina** y un **cocinero literal**:

- La receta es el **código fuente**.
- Un **traductor** que convierte la receta al idioma del cocinero es el **compilador**: si la receta está en un idioma inexistente o le faltan palabras clave, no puede traducirla. (Error de compilación.)
- **Cocinar** es la **ejecución**. Si la receta dice "añade el huevo" y no hay huevos, el cocinero se detiene a mitad. (Error de ejecución.)
- Si la receta dice "añade sal" donde debía decir "añade azúcar", el cocinero obedece, termina el plato… y sale mal. (Error lógico.)

**Dónde falla la analogía:** un cocinero real improvisa y usa sentido común; una computadora no. Tampoco se cansa: ejecuta millones de pasos por segundo y repite siempre el mismo resultado con los mismos datos.

## 5. Ejemplos comentados

### Ejemplo 1 · Las instrucciones se ejecutan en orden

<!--v
modo: ejecuta
salida: siguiente
-->
```csharp
Console.WriteLine("Inicio");
Console.WriteLine("Medio");
Console.WriteLine("Fin");
```

```text
Inicio
Medio
Fin
```

El programa va de arriba abajo, una instrucción tras otra. Si cambias el orden de las líneas, cambia el orden de la salida.

### Ejemplo 2 · `Write` y `WriteLine`

<!--v
modo: ejecuta
salida: siguiente
-->
```csharp
Console.WriteLine("Línea 1");
Console.Write("Sin salto ");
Console.Write("de línea");
Console.WriteLine();
Console.WriteLine("Línea 3");
```

```text
Línea 1
Sin salto de línea
Línea 3
```

`Write` escribe **sin** saltar de línea; `WriteLine` escribe y **salta**. `WriteLine()` sin datos solo salta de línea.

### Ejemplo 3 · Entrada, proceso, salida con datos fijos

<!--v
modo: ejecuta
salida: siguiente
-->
```csharp
int ancho = 8;
int alto = 3;
int area = ancho * alto;
Console.WriteLine("El área es: " + area);
```

```text
El área es: 24
```

- `int ancho = 8;` crea una **variable** llamada `ancho` que guarda el entero `8`. (`int` es el *tipo*: "número entero". Variables y tipos se estudian a fondo en la unidad 1.1.)
- `int area = ancho * alto;` calcula `8 * 3` y guarda `24` en `area`.
- `"El área es: " + area` **une** un texto con un número y produce el texto `El área es: 24`.

---

## 6. Análisis del código

Qué pasa en el Ejemplo 3, línea por línea. La columna *Memoria* muestra qué valores existen después de ejecutar la línea:

| Línea | Instrucción | `ancho` | `alto` | `area` | Salida |
|---|---|---|---|---|---|
| 1 | `int ancho = 8;` | 8 | — | — | |
| 2 | `int alto = 3;` | 8 | 3 | — | |
| 3 | `int area = ancho * alto;` | 8 | 3 | 24 | |
| 4 | `Console.WriteLine(...)` | 8 | 3 | 24 | `El área es: 24` |

Dos observaciones que usarás siempre:

1. **El orden importa.** En la línea 3, `ancho` y `alto` ya tienen valor porque las líneas 1 y 2 se ejecutaron antes. El compilador te lo exige: usar una variable **antes** de crearla es un error (lo verás en la sección 7).
2. **Una variable guarda un valor**, no una fórmula. `area` vale 24 aunque después cambies `ancho`; habría que recalcular.

**Técnica obligatoria desde hoy:** antes de ejecutar un programa, *predice* qué mostrará (en papel o en voz alta). Después ejecuta. Si no coinciden, ahí hay algo que aprender.

## 7. Errores frecuentes

### Error 1 · Falta un punto y coma (compilación)

<!--v
modo: error CS1002
-->
```csharp
Console.WriteLine("Hola, mundo")
```

El compilador responde con algo como `error CS1002: ; expected`. **El código (`CS1002`) es lo que debes mirar**: el texto puede estar en español en tu entorno. **Corrección:** añadir `;` al final.

### Error 2 · Mayúsculas incorrectas (compilación)

<!--v
modo: error CS0103
-->
```csharp
console.WriteLine("Hola, mundo");
```

`CS0103`: *el nombre 'console' no existe en el contexto actual*. C# distingue mayúsculas: debe ser `Console`. **Corrección:** respetar el nombre exacto.

### Error 3 · Comillas sin cerrar (compilación; un error arrastra a otros)

<!--v
modo: error CS1010
-->
```csharp
Console.WriteLine("Hola, mundo);
```

Aparece `CS1010` (*nueva línea en constante*) y, además, `CS1002` y `CS1026`. **Regla:** cuando hay varios errores, **corrige el primero** y vuelve a compilar; los demás suelen ser consecuencia.

### Error 4 · Usar una variable antes de crearla (compilación)

<!--v
modo: error CS0841
-->
```csharp
int area = ancho * alto;
int ancho = 8;
int alto = 3;
Console.WriteLine(area);
```

`CS0841`: no se puede usar la variable local antes de declararla. **Corrección:** declarar `ancho` y `alto` **antes** de la línea que las usa.

### Error 5 · División entre cero (ejecución)

<!--v
modo: excepcion DivideByZeroException
salida: siguiente
-->
```csharp
int cero = 0;
Console.WriteLine("Antes");
Console.WriteLine(10 / cero);
Console.WriteLine("Después");
```

```text
Antes
```

El programa **compila** y arranca, imprime `Antes` y se cae con `System.DivideByZeroException` en la línea 3. `Después` nunca se muestra. Fíjate: **lo que se imprimió antes del fallo se conserva**; lo posterior no existe.

**Comparación útil:** si escribes la división con el literal `10 / 0`, el compilador lo detecta antes de ejecutar:

<!--v
modo: error CS0020
-->
```csharp
Console.WriteLine(10 / 0);
```

`CS0020`: *división por una constante cero*. Cuando el valor viene de una variable, el compilador no puede saberlo y el error aparece al ejecutar.

### Error 6 · Error lógico (nadie avisa)

<!--v
modo: ejecuta
salida: siguiente
-->
```csharp
int ancho = 8;
int alto = 3;
int area = ancho + alto;
Console.WriteLine("Área: " + area);
```

```text
Área: 11
```

Compila, ejecuta y muestra un número… **equivocado**: el área es 24. La causa (sumar en vez de multiplicar) solo se encuentra **comparando con el resultado que esperabas**. Por eso predices antes de ejecutar.

## 8. Variaciones

1. **Cambian los datos.** Cambia `8` y `3` por otros valores y predice el área antes de ejecutar.
2. **Cambia la fórmula.** Perímetro: `2 * (ancho + alto)`. Paréntesis: `2 * ancho + alto` da otro resultado. Mira por qué en la traza.
3. **Cambia la figura.** Área de un triángulo: `base * altura / 2`. Prueba con `7` y `3`:

<!--v
modo: ejecuta
salida: siguiente
-->
```csharp
int baseTriangulo = 7;
int alturaTriangulo = 3;
Console.WriteLine(baseTriangulo * alturaTriangulo / 2);
Console.WriteLine(baseTriangulo * alturaTriangulo / 2.0);
```

```text
10
10.5
```

La primera línea muestra `10`, no `10.5`: dividir **enteros** entre **enteros** da un entero (descarta el decimal). La segunda usa `2.0` y sí da `10.5`. No lo resolvemos hoy: es la razón de que la unidad 1.1 estudie los **tipos**. Anótalo como pregunta.

> Nota sobre decimales: el texto de salida puede aparecer como `10,5` en tu equipo, según la configuración regional. Es normal.

> No uses `base` como nombre de variable: es una **palabra reservada** de C# y da un error de compilación (`CS1001`). Por eso aquí se escribe `baseTriangulo`.
