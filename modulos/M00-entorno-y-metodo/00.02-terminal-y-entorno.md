## 3. Explicación desde cero

### 3.1 Qué es la terminal

La **terminal** es una ventana donde escribes **órdenes de texto** (comandos) para que la computadora las ejecute. El programa que interpreta lo que escribes se llama **shell**:

| Sistema | Shell habitual | Terminal |
|---|---|---|
| Windows 10/11 | **PowerShell** | Windows Terminal o la consola de PowerShell |
| macOS | zsh | Terminal |
| Linux | bash | la que traiga tu distribución |

¿Por qué aprenderla si existen ventanas y ratón? Porque casi todo lo importante del curso se hace con comandos: `dotnet`, `git`, ejecutar pruebas, publicar. Un comando es **repetible, escribible y exacto**: puedes copiarlo en tu bitácora y reproducirlo mañana.

> **Convención de este curso:** los ejemplos usan PowerShell de Windows. Los comandos `ls`, `cd`, `pwd`, `mkdir`, `cat`, `cp`, `mv` y `rm` funcionan igual en PowerShell que en bash, lo que facilita el cambio de sistema. Solo cambian las barras de las rutas (`\` en Windows, `/` en macOS y Linux).

### 3.2 El sistema de archivos y las rutas

Los archivos viven en **carpetas** (o *directorios*), que a su vez están dentro de otras carpetas, formando un **árbol**. Una **ruta** es la dirección de un archivo o carpeta dentro de ese árbol.

```text
C:\Estudio
├── practica
│   ├── semana-01
│   │   └── hola
│   └── notas
└── recursos
```

- **Ruta absoluta:** empieza desde la raíz y sirve desde cualquier lugar. Ejemplo: `C:\Estudio\practica\notas`.
- **Ruta relativa:** se interpreta desde el **directorio actual** (*current working directory*, "dónde estás ahora"). Ejemplo: estando en `C:\Estudio\practica`, la ruta `semana-01\hola` apunta a `C:\Estudio\practica\semana-01\hola`.
- **Símbolos especiales:** `.` es "esta carpeta"; `..` es "la carpeta de arriba" (el *padre*).

Una **extensión** (`.cs`, `.txt`, `.csproj`) es la parte final del nombre tras el último punto e indica el tipo de archivo. **Activa "Extensiones de nombre de archivo" en el Explorador de Windows** (pestaña *Vista*): si no, `Program.cs.txt` se ve como `Program.cs` y nada funciona.

### 3.3 Comandos esenciales

| Para… | PowerShell | bash/zsh | Nota |
|---|---|---|---|
| Ver dónde estoy | `pwd` | `pwd` | También `Get-Location`. |
| Listar el contenido | `ls` | `ls` | En Windows también `dir`. |
| Entrar a una carpeta | `cd practica` | `cd practica` | |
| Subir un nivel | `cd ..` | `cd ..` | |
| Crear una carpeta | `mkdir semana-01` | `mkdir semana-01` | |
| Crear un archivo vacío | `New-Item notas.txt` | `touch notas.txt` | |
| Ver el contenido de un archivo | `cat notas.txt` | `cat notas.txt` | |
| Copiar | `cp a.txt b.txt` | `cp a.txt b.txt` | |
| Mover o renombrar | `mv a.txt carpeta\` | `mv a.txt carpeta/` | |
| Borrar un archivo | `rm a.txt` | `rm a.txt` | **No hay papelera.** |
| Limpiar la pantalla | `cls` | `clear` | |

Atajos que te ahorrarán horas:

- **Tabulador:** autocompleta nombres. Escribe `cd pra` + `Tab`.
- **Flecha arriba:** repite comandos anteriores.
- **`Ctrl + C`:** interrumpe un comando que se quedó ejecutando.
- **Comillas:** si una ruta tiene espacios, entre comillas: `cd "Mis Documentos"`. Mejor aún: **evita espacios, tildes y `ñ` en los nombres de carpetas de trabajo**.

> **Cuidado con borrar.** `rm` y `Remove-Item` no mandan nada a la papelera. Antes de borrar, haz `ls` y lee. Para carpetas completas, en PowerShell usa `Remove-Item -Recurse nombre-carpeta`; **no** copies `rm -rf` de tutoriales de Linux (en PowerShell falla por ambigüedad de parámetros y en otros shells puede ser destructivo). Solo borra dentro de tu carpeta `practica/`.

### 3.4 Qué debes tener instalado

| Herramienta | Para qué | Cómo conseguirla | Cómo verificarla |
|---|---|---|---|
| **.NET SDK 10** | Compilar y ejecutar C#. | [dotnet.microsoft.com/download/dotnet/10.0](https://dotnet.microsoft.com/en-us/download/dotnet/10.0) (elige **SDK**, no solo Runtime), o `winget install Microsoft.DotNet.SDK.10`. | `dotnet --version` debe mostrar `10.0.xxx`. |
| **Un editor** | Escribir y depurar. | Elige **uno**: **Visual Studio 2026 Community** (Windows) o **VS Code** con la extensión de C#. Ver 3.5. | Abrir y crear un proyecto de consola. |
| **Git** | Control de versiones. | [git-scm.com](https://git-scm.com/install/windows) o `winget install --id Git.Git -e`. | `git --version`. |
| **SQL Server** | Base de datos (se usa desde el módulo 5). | **Developer** o **Express** (2022 o 2025), vía el instalador oficial. | Conectarte con SSMS o con la extensión MSSQL y ejecutar `SELECT @@VERSION;`. |
| **Herramienta SQL** | Consultar y administrar. | **SSMS 22** (se instala con el Visual Studio Installer, no es un MSI independiente) o la **extensión MSSQL de VS Code**. | Ver más abajo. |

> Lo que **no puedo hacer por ti**: instalar nada en tu equipo. Tú ejecutas los instaladores; yo te ayudo a leer errores. Descarga siempre desde las páginas oficiales de Microsoft y de Git.

### 3.5 Visual Studio o VS Code

| Si… | Elige |
|---|---|
| Usas Windows y ya conoces Visual Studio (WinForms, diseñadores) | **Visual Studio 2026 Community**: depurador integrado, asistente de paquetes y diseñadores. Carga de trabajo: *Desarrollo de ASP.NET y web* y *Desarrollo de escritorio con .NET*. |
| Quieres ligereza o usas macOS/Linux | **VS Code** + extensión **C#**. El **C# Dev Kit** es opcional, requiere iniciar sesión y tiene sus propios términos de licencia: léelos antes de instalarlo. |

Da igual cuál elijas: **todo el curso se puede seguir con la CLI de `dotnet` y con cualquiera de los dos editores**. Aprender los comandos te hace independiente del editor.

### 3.6 Registrar versiones: la ficha de entorno

Apunta en tu bitácora lo que tienes instalado (fecha incluida). Cuando algo falle, lo primero que se pregunta es "¿qué versiones tienes?". La plantilla está en los retos (R-0.2-N2-B).

## 4. Analogía intuitiva

- **La terminal es una conversación por mensajes con la computadora**; el explorador de archivos es manejar con volante y pedales. Con el volante es cómodo, pero el mensaje se puede copiar, repetir y automatizar.
- **El directorio actual** es *la habitación de la casa en la que estás*. Una **ruta absoluta** es la dirección postal completa; una **ruta relativa** es "sube un piso y entra por la segunda puerta": solo tiene sentido si sabes dónde estás ahora.

**Dónde falla:** si te equivocas de habitación, la computadora no te lo dice: crea el archivo en la habitación donde *estás*, que puede no ser donde pensabas.

## 5. Ejemplos comentados

### Ejemplo 1 · Recorrido por el árbol (PowerShell)

*(Comandos no ejecutados en Windows en el entorno de construcción; el comportamiento de `cd` y de las rutas relativas se contrastó con un árbol equivalente en bash.)*

```powershell
cd C:\Estudio
cd practica
cd semana-01
cd ..
cd ..\recursos
cd C:\Estudio\practica\notas
cd ..\..
```

Traza del **directorio actual** tras cada comando:

| Comando | Directorio actual después |
|---|---|
| `cd C:\Estudio` | `C:\Estudio` |
| `cd practica` | `C:\Estudio\practica` |
| `cd semana-01` | `C:\Estudio\practica\semana-01` |
| `cd ..` | `C:\Estudio\practica` |
| `cd ..\recursos` | `C:\Estudio\recursos` |
| `cd C:\Estudio\practica\notas` | `C:\Estudio\practica\notas` |
| `cd ..\..` | `C:\Estudio` |

Observa: `cd practica` es **relativo** (depende de dónde estás); `cd C:\Estudio\practica\notas` es **absoluto** (funciona siempre). `cd ..\recursos` sube un nivel y baja a `recursos` en un solo paso.

### Ejemplo 2 · Crear una estructura de trabajo

```powershell
cd C:\Estudio\practica
mkdir semana-01
cd semana-01
mkdir 00-01
mkdir 00-02
ls
```

Crea `semana-01` dentro de `practica`, entra en ella y crea dos carpetas. Al final `ls` muestra `00-01` y `00-02`. **Todo se creó en el directorio donde estabas**: por eso el primer comando es un `cd` explícito.

### Ejemplo 3 · Verificar el entorno

```powershell
dotnet --version
dotnet --list-sdks
git --version
```

- `dotnet --version`: el SDK que se usará (para la ruta del curso debe empezar por `10.0`).
- `dotnet --list-sdks`: todos los SDK instalados con su carpeta. Si la lista está vacía tienes solo el runtime.
- `git --version`: una línea del estilo `git version 2.xx.x`.

Salida típica de `dotnet --version` (los números finales varían):

```text
10.0.xxx
```

### Ejemplo 4 · La prueba de humo

*(Equivale a los comandos verificados con .NET SDK 10 en Linux. La salida `Hello, World!` es la que genera la plantilla de .NET 10.)*

```powershell
cd C:\Estudio\practica\semana-01
dotnet new console -n Hola
cd Hola
dotnet run
```

Al final se muestra:

```text
Hello, World!
```

La **primera vez** que usas `dotnet` en un equipo nuevo puede salir un mensaje de bienvenida y un aviso sobre la telemetría. Es normal; léelo. En la unidad 0.3 se explica qué crea `dotnet new`.

### Ejemplo 5 · Verificar SQL Server

*(Pasos para SSMS 22; no ejecutados en este entorno.)*

1. Abre **SSMS 22** y en *Connect to Server* escribe el nombre del servidor. Según tu instalación: `localhost`, `.\SQLEXPRESS` o `(localdb)\MSSQLLocalDB`.
2. Elige *Windows Authentication* si te lo pide el instalador.
3. Si aparece un error de **certificado no confiable** en un servidor de **desarrollo** local, el cuadro de conexión tiene la opción *Trust server certificate*. Úsala **solo en tu equipo de desarrollo**.
4. Abre una *New Query* y ejecuta:

```sql
SELECT @@VERSION;
```

Debe devolver una fila con texto que empieza por `Microsoft SQL Server`. Anota el resultado en tu ficha de entorno.

## 6. Análisis del código

Qué ocurre exactamente al ejecutar el Ejemplo 4:

1. **`cd`** cambia el directorio actual del shell. Todo lo que sigue se ejecuta "desde ahí".
2. **`dotnet new console -n Hola`** crea la carpeta `Hola` **dentro del directorio actual** con los archivos de un proyecto de consola (`Hola.csproj`, `Program.cs`) y, según el SDK, restaura paquetes.
3. **`cd Hola`** entra en la carpeta recién creada. Es necesario porque `dotnet run` busca el proyecto **en el directorio actual**.
4. **`dotnet run`** compila el proyecto y, si compila, lo ejecuta. Si hay errores, los muestra y no ejecuta nada.

**Qué puedes comprobar:** si ejecutas `dotnet run` *sin* entrar a `Hola`, el comando falla porque no encuentra un proyecto. Eso confirma que `dotnet run` depende del directorio actual.

## 7. Errores frecuentes

| Síntoma | Causa más probable | Cómo se corrige |
|---|---|---|
| `dotnet : El término 'dotnet' no se reconoce como nombre de un cmdlet…` | La terminal se abrió **antes** de instalar y no ve el cambio de `PATH`, o no se instaló. | **Cierra y abre** la terminal. Si persiste, vuelve a ejecutar el instalador y comprueba que terminó sin errores. |
| `dotnet --version` muestra `8.x` o `9.x` | Tienes otro SDK que se usa por defecto, o instalaste solo el runtime de 10. | `dotnet --list-sdks` muestra todos. Instala el SDK 10. Si hay un archivo `global.json` en una carpeta superior, puede estar fijando una versión: ábrelo y léelo antes de tocar nada. |
| `dotnet new console` dice que no encuentra SDK | Solo está instalado el **runtime**. | Instala el **SDK**. |
| El proyecto se creó en `C:\Windows\System32` o en tu carpeta de usuario | Ejecutaste el comando sin comprobar `pwd`. | `pwd` **siempre** antes de crear nada. Mueve el proyecto a `practica/`. |
| `cd Mis Documentos` falla | Los espacios separan argumentos. | Usa comillas, o evita espacios en nombres. |
| `Program.cs.txt` | Extensiones de nombre ocultas en el Explorador. | Actívalas y renombra. |
| Errores raros de compilación en `bin` u `obj` | Carpeta de trabajo dentro de un directorio sincronizado (p. ej. OneDrive) que bloquea archivos. | Trabaja fuera de carpetas sincronizadas. Una ruta corta como `C:\Estudio` evita muchos problemas. |
| `rm -rf` en PowerShell da error | `-rf` no es válido en PowerShell. | `Remove-Item -Recurse carpeta`. |
| SSMS no se conecta | Servicio detenido, nombre de instancia incorrecto, o certificado no confiable. | Comprueba el nombre exacto de la instancia, que el servicio *SQL Server* está iniciado (Servicios de Windows) y la opción *Trust server certificate* en desarrollo. |

## 8. Variaciones

- **Otro sistema operativo.** En macOS/Linux, las barras son `/` y no existe `C:`. Ejemplo equivalente: `cd ~/estudio/practica`. La instalación de SSMS **solo existe para Windows**: en macOS/Linux la herramienta SQL será la extensión MSSQL de VS Code, y SQL Server correrá en un contenedor (Docker) u otra instancia; si ese es tu caso, avísame y adaptamos esa parte.
- **Otro editor.** Todo lo que haces con `dotnet` en la terminal es idéntico con Visual Studio o VS Code; solo cambia dónde pulsas el botón de ejecutar.
- **Ruta distinta.** Si tu carpeta de trabajo es `D:\Cursos\csharp`, cambia el prefijo de las rutas absolutas; las relativas siguen igual.
- **Azure Data Studio.** Dejó de recibir soporte el 28 de febrero de 2026; Microsoft indica la extensión MSSQL de VS Code como alternativa. No se usa en este curso.
