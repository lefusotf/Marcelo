## R-0.3-N1-A · Leer un `.csproj`

| Línea | Qué significa |
|---|---|
| `Sdk="Microsoft.NET.Sdk"` | Usa las reglas de compilación del SDK de .NET. |
| `OutputType` = `Library` | El resultado es una **biblioteca** (código reutilizable), **no** un ejecutable. |
| `TargetFramework` = `net8.0` | Se compila para .NET 8, no 10. |
| `ImplicitUsings` = `disable` | No se importan espacios de nombres automáticamente. |
| `Nullable` = `disable` | El compilador no emite advertencias de nulabilidad. |

1. `dotnet run` **se niega**: con `OutputType` `Library` responde que debes tener un tipo de proyecto ejecutable (necesita un TFM ejecutable y `OutputType` `Exe`). *(Mensaje comprobado con SDK 10.)*
2. **No compila** si no añades `using System;` (o `System.Console`): error `CS0103`, *el nombre 'Console' no existe en el contexto actual*. *(Comprobado con SDK 10.)*
3. Dejas de recibir **advertencias** `CS86xx` sobre posibles valores nulos. No es que los nulos no existan: simplemente no te avisan.
4. Para ejecutar un programa que apunta a `net8.0` necesitas el **runtime de .NET 8** instalado; el SDK 10 puede compilarlo, pero por defecto no ejecuta una aplicación de .NET 8 con el runtime 10.

## R-0.3-N1-B · `git status --short`

| N.º | Salida | Significado |
|---|---|---|
| 1 | `?? Saludo/` | Carpeta nueva que Git aún **no sigue**. |
| 2 | `A  Saludo/Program.cs` y `A  Saludo/Saludo.csproj` | Archivos nuevos **preparados** para el commit. |
| 3 | *(nada)* | Sin cambios pendientes. |
| 4 | ` M Saludo/Program.cs` | Modificado, **sin preparar** (la `M` está en la segunda columna). |
| 5 | `MM Saludo/Program.cs` | Una versión está preparada **y** hay más cambios posteriores sin preparar. *(Comprobado.)* |

El caso 5 es el que más confunde: el commit guardaría la versión de cuando hiciste `add`, no la última que escribiste. Hay que volver a hacer `git add`.

## R-0.3-N1-C · Mensajes de commit

| N.º | Valoración | Por qué | Reescritura |
|---|---|---|---|
| 1 | **Malo** | No dice qué cambió. | `Corrige una falta de ortografía en el README` |
| 2 | **Bueno** | Concreto: qué y dónde. | — |
| 3 | **Malo** | Mezcla tres cambios sin relación. | Tres commits: `Agrega el reto 2`, `Cambia el .gitignore para excluir bin y obj`, y el arreglo concreto |
| 4 | **Bueno** | Dice qué y por qué. | — |
| 5 | **Malo** | Sin información. | `Crea el proyecto del reto N2-A` |
| 6 | **Malo** | Vago: ¿qué se actualizó? | `Cambia el texto de bienvenida del programa` |

**Por qué el 3 es un problema de proceso:** significa que se acumularon varios cambios y se confirmaron juntos. Sin commits pequeños, no se puede revertir un cambio sin arrastrar los demás, ni entender qué hizo qué.

## R-0.3-N2-A · Un proyecto, tres commits

Secuencia (PowerShell o bash; solo cambian las barras):

```text
cd practica/semana-01/00-03-proyecto
dotnet new console -n Saludo
git status
git add Saludo
git commit -m "Crea el proyecto Saludo"

(edita Program.cs con dos líneas, guarda)
dotnet run
git status
git add Saludo/Program.cs
git commit -m "Muestra dos líneas de bienvenida"

(añade la tercera línea, guarda)
dotnet run
git status
git add Saludo/Program.cs
git commit -m "Agrega la tercera línea de bienvenida"
git log --oneline
```

Un `Program.cs` válido al final:

2. `git ls-files <ruta>` muestra solo `Saludo.csproj` y `Program.cs` (los archivos de código, no los generados).

## R-0.3-N3-B · `git init` en una carpeta de ensayo

```text
mkdir C:\EnsayoGit
cd C:\EnsayoGit
git init
git status
(crea notas.txt con una línea)
git add notas.txt
git commit -m "Crea notas.txt"
(añade una segunda línea)
git diff
git add notas.txt
git commit -m "Agrega una segunda línea a notas.txt"
git log --oneline
```

`git diff` muestra los cambios aún no preparados: las líneas añadidas con `+` y las eliminadas con `-`. Salida real de un ensayo equivalente:

```text
@@ -1,2 +1,3 @@
 a
 b
+c
```

`git status` fuera de cualquier repositorio responde (comprobado):

```text
fatal: not a git repository (or any of the parent directories): .git
```

**Caso límite:** `git log` justo después de `git init`, sin commits, responde que la rama actual **no tiene commits todavía**.

**Qué es `.git`:** la carpeta (oculta) que guarda **todo el historial** y la configuración del repositorio. Borrarla equivale a borrar el historial; el resto de archivos queda como archivos sueltos.

**Para borrar la carpeta de ensayo con seguridad:** antes, `pwd` y `ls`; confirma que es la carpeta de ensayo; borra solo esa.

## R-0.3-N4-A · Rompí mi programa

Se ejecutó de principio a fin en un repositorio temporal. Resultados reales:

**Paso 3 · compilar el programa roto:**

```text
Program.cs(2,34): error CS1002: ; expected
```

**Paso 4 · historial y localización.** `git log --oneline` mostraba:

```text
fb3d6cf Agrega una nota al diario
852b518 Cambia el saludo
e7f3026 Agrega la tercera linea de bienvenida
a36478e Muestra dos lineas de bienvenida
f39360c Crea el proyecto Saludo
```

Para localizar al culpable se comparan versiones consecutivas del archivo con `git diff <commit-anterior> <commit> -- ruta` hasta encontrar el cambio que introduce el error (aquí, `git diff e7f3026 852b518 -- Saludo/Program.cs`). El diff mostró:

```text
-Console.WriteLine("Bienvenida 2");
+Console.WriteLine("Bienvenida 2")
```

El commit `852b518 Cambia el saludo` quitó el `;`.

**Paso 5 · restaurar solo el archivo roto desde el último commit bueno (`HEAD~2` en ese momento):**

```text
git restore --source=HEAD~2 -- Saludo/Program.cs
```

`git status --short` mostró ` M Saludo/Program.cs` (el archivo vuelve a su versión buena pero aparece **modificado** respecto al último commit) y ` M notas/diario.txt` (el cambio sin confirmar **sobrevivió**).

**Paso 6 · comprobar y confirmar la reparación.** `dotnet run` mostró las tres líneas. Luego:

```text
git add Saludo/Program.cs
git commit -m "Restaura Program.cs a la versión que compilaba"
```

**Historial final:** los seis commits (reparación, nota, roto y los tres anteriores), con el commit roto **conservado**.

**Por qué no `git reset --hard`:** `reset --hard` mueve el historial y **descarta cambios no confirmados** de todo el árbol (el cambio sin confirmar de `notas/diario.txt` se habría perdido). Además reescribe lo que ves como "pasado" y, si ya hubieras hecho `push`, descoordina el repositorio remoto. `git restore` de un solo archivo es la herramienta precisa.

**Sobre `git restore` con cambios que sí querías:** `git restore ruta` sin `--source` **descarta** los cambios no confirmados de ese archivo, sin posibilidad de deshacerlo. Con `--source=<commit>` también sobrescribe el archivo en el directorio de trabajo. Por eso se mira `git status` y `git diff` antes.

**Errores frecuentes cubiertos:** confirmar la reparación sin compilar; restaurar todo el árbol; olvidar que el commit roto sigue en el historial (es correcto que siga).
