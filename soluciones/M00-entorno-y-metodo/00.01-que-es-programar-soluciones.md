## R-0.1-N1-A · Clasificar errores

| N.º | Momento | Tipo | Qué verías |
|---|---|---|---|
| 1 | Al compilar | Compilación | `CS1010` (nueva línea en constante) y otros arrastrados; no hay programa. |

## R-0.1-N1-B · Ordenar el recorrido

Orden correcto: **C → D → A → E → B → F → G**.

| Paso | Elemento | ¿Acción o producto? |
|---|---|---|
| 1 | C. `Program.cs` | Producto (lo escribes tú) |
| 2 | D. El compilador revisa y traduce | **Acción** |
| 3 | A. Archivo `.dll` con IL | Producto |
| 4 | E. El JIT traduce IL a código de máquina | **Acción** |
| 5 | B. Código de máquina | Producto |
| 6 | F. La CPU ejecuta | **Acción** |
| 7 | G. Resultado en la consola | Producto |

*Por qué no se compila directamente a código de máquina:* el IL es independiente del procesador y del sistema operativo; el JIT genera el código de máquina concreto para la computadora donde se ejecuta. Así el mismo `.dll` corre en distintas plataformas con el runtime de .NET adecuado.

## R-0.1-N1-C · Predecir la salida

**Programa 1**

<!--v

-->
```csharp
Console.WriteLine(2 + 3 * 4);
Console.WriteLine((2 + 3) * 4);
Console.WriteLine("2 + 3 * 4");
```

```text
14
20
2 + 3 * 4
```

`*` precede a `+` (14); los paréntesis lo cambian (20); entre comillas es solo texto.

**Programa 2**

<!--v
modo: ejecuta
salida: siguiente
-->
```csharp
int a = 10;
int b = 3;
a = a + b;
b = a - b;
Console.WriteLine(a);
Console.WriteLine(b);
```

```text
13
10
```

| Tras la línea | `a` | `b` |
|---|---|---|
| `int a = 10;` | 10 | — |
| `int b = 3;` | 10 | 3 |
| `a = a + b;` | 13 | 3 |
| `b = a - b;` | 13 | 10 |

`=` **asigna**: toma el valor de la derecha y lo guarda a la izquierda. Es un intercambio parcial: `b` acaba valiendo el `a` original.

## R-0.1-N1-D · Explicar código

<!--v
modo: ejecuta
salida: siguiente
-->
```csharp
int cantidad = 5;
int precioUnitario = 4;
int envio = 3;
int subtotal = cantidad * precioUnitario;
int total = subtotal + envio;
Console.WriteLine("Subtotal: " + subtotal);
Console.WriteLine("Total: " + total);
```

```text
Subtotal: 20
Total: 23
```

**Explicación esperada (una posible):** se guardan tres datos; el subtotal es la cantidad por el precio de cada unidad; el total suma el envío al subtotal; se muestran ambos resultados con una etiqueta.

| Línea | `cantidad` | `precioUnitario` | `envio` | `subtotal` | `total` |
|---|---|---|---|---|---|
| 1 | 5 | — | — | — | — |
| 2 | 5 | 4 | — | — | — |
| 3 | 5 | 4 | 3 | — | — |
| 4 | 5 | 4 | 3 | 20 | — |
| 5 | 5 | 4 | 3 | 20 | 23 |

- Si `envio` valiera `0`: `Subtotal: 20` y `Total: 20`.
- Para dos pedidos iguales: `int total = 2 * subtotal + envio;` (si el envío se paga una sola vez) o `2 * (subtotal + envio)` (si se paga por pedido). **Hay dos interpretaciones válidas; un buen ingeniero pregunta cuál es la correcta** (requisito ambiguo).

## R-0.1-N2-A · Modificar el programa del área

<!--v
modo: ejecuta
salida: siguiente
-->
```csharp
int ancho = 8;
int alto = 3;

Console.WriteLine("Rectángulo de " + ancho + " x " + alto);
Console.WriteLine("Área: " + ancho * alto);
Console.WriteLine("Perímetro: " + 2 * (ancho + alto));
Console.WriteLine("Área del triángulo: " + ancho * alto / 2);
```

```text
Rectángulo de 8 x 3
Área: 24
Perímetro: 22
Área del triángulo: 12
```

Se calcula dentro de la propia expresión; en `"Área: " + ancho * alto` la multiplicación se hace **antes** de unir porque `*` precede a `+`. Es correcto, pero para legibilidad también es válido guardar cada resultado en una variable (`int area = ancho * alto;`) y mostrarla.

Segundo juego de datos (5 × 5):

<!--v
modo: ejecuta
salida: siguiente
-->
```csharp
int ancho = 5;
int alto = 5;

Console.WriteLine("Rectángulo de " + ancho + " x " + alto);
Console.WriteLine("Área: " + ancho * alto);
Console.WriteLine("Perímetro: " + 2 * (ancho + alto));
Console.WriteLine("Área del triángulo: " + ancho * alto / 2);
```

```text
Rectángulo de 5 x 5
Área: 25
Perímetro: 20
Área del triángulo: 12
```

**Por qué `12` y no `12.5`:** `25 / 2` con enteros es una división entera (descarta la parte decimal). Se resolverá con el tipo `double` en la unidad 1.1.

**Qué revisar en tu solución:** ningún número `8`, `3`, `5` escrito dos veces; `2 * (ancho + alto)` con paréntesis; espacios correctos dentro de las comillas.

## R-0.1-N2-C · El robot literal

**Algoritmo de referencia**

1. Leer la primera nota y llamarla `n1`.
2. Leer la segunda nota y llamarla `n2`.
3. Leer la tercera nota y llamarla `n3`.
4. Calcular `suma = n1 + n2 + n3`.
5. Calcular `promedio = suma ÷ 3` (división con decimales).
6. Si `promedio` es mayor o igual a 6, escribir `Aprueba` y terminar.
7. En caso contrario, escribir `Reprueba` y terminar.

**Trazas**

| Notas | `suma` | `promedio` | ¿≥ 6? | Salida |
|---|---|---|---|---|
| 7, 5, 8 | 20 | 6.67 | Sí | `Aprueba` |
| 4, 5, 6 | 15 | 5 | No | `Reprueba` |
| 6, 6, 6 | 18 | 6 | **Sí** (igual cuenta) | `Aprueba` |

**Puntos que el robot mira:** los pasos 6 y 7 son excluyentes y cubren *todos* los valores posibles; el paso 5 especifica división con decimales (si fuera entera, 6.67 sería 6 y el caso límite engañaría); cada paso usa solo datos ya producidos.

**Variante frecuente que falla:** "si es mayor que 6 aprueba" deja fuera el `6, 6, 6`.

## R-0.1-N3-A · Recibo de compra

<!--v
modo: ejecuta
salida: siguiente
-->
```csharp
int cantidadCuadernos = 4;
int precioCuaderno = 5;
int cantidadLapices = 10;
int precioLapiz = 1;
int cantidadCarpetas = 2;
int precioCarpeta = 10;

int totalCuadernos = cantidadCuadernos * precioCuaderno;
int totalLapices = cantidadLapices * precioLapiz;
int totalCarpetas = cantidadCarpetas * precioCarpeta;

int subtotal = totalCuadernos + totalLapices + totalCarpetas;
int impuesto = subtotal * 10 / 100;
int total = subtotal + impuesto;

Console.WriteLine("===== RECIBO =====");
Console.WriteLine("Cuaderno: " + cantidadCuadernos + " x " + precioCuaderno + " = " + totalCuadernos);
Console.WriteLine("Lápiz: " + cantidadLapices + " x " + precioLapiz + " = " + totalLapices);
Console.WriteLine("Carpeta: " + cantidadCarpetas + " x " + precioCarpeta + " = " + totalCarpetas);
Console.WriteLine("Subtotal: " + subtotal);
Console.WriteLine("Impuesto (10%): " + impuesto);
Console.WriteLine("Total: " + total);
```

```text
===== RECIBO =====
Cuaderno: 4 x 5 = 20
Lápiz: 10 x 1 = 10
Carpeta: 2 x 10 = 20
Subtotal: 50
Impuesto (10%): 5
Total: 55
```

**Prueba 2 (cuadernos = 6):** solo cambia `int cantidadCuadernos = 6;`. La salida debe contener `Cuaderno: 6 x 5 = 30`, `Subtotal: 60`, `Impuesto (10%): 6`, `Total: 66`.

salida-contiene: Subtotal: 60

**Qué revisar en tu solución:** ningún resultado escrito a mano; cada número (cantidad o precio) una sola vez; nombres que se entienden sin comentarios.

## R-0.1-N3-B · Fabrica tus propios errores (ejemplos válidos)

No hay una única respuesta correcta. Ejemplos que cumplen las condiciones:

**Compilación (distinto código):** `CS0266` por asignar un `double` a un `int`.

<!--v
modo: error CS0266
-->
```csharp
int precio = 9.99;
Console.WriteLine(precio);
```

**Ejecución (excepción distinta):** convertir un texto que no es número.

<!--v
modo: excepcion FormatException
-->
```csharp
Console.WriteLine("Antes");
int cantidad = int.Parse("doce");
Console.WriteLine(cantidad);
```

Aquí el compilador no lo detecta: `int.Parse` recibe un texto válido; que ese texto no sea un número se descubre al ejecutar.

**Lógico:** una fórmula con el operador equivocado.

<!--v
modo: ejecuta
salida: siguiente
-->


```text
Perímetro: 14
```

El perímetro es `2 * (largo + ancho)` = 28. El programa "funciona" y miente.

**Qué revisar:** que cada error sea de verdad del tipo que dices; que hayas copiado la salida real; y que una persona pueda reconocer el tipo sin que se lo expliques.

## R-0.1-N4-A · Un programa que no escribiste

**Ruta de depuración (cada paso es una ejecución distinta):**

1. **Programa original.** No compila: falta el `;` de la línea del `Console.WriteLine("Pago bruto: "...)`.

<!--v
modo: error CS1002
-->
```csharp
int horas = 40;
int tarifa = 12;
int diasTrabajados = 0;

int pagoBruto = horas + tarifa;
int pagoPorDia = pagoBruto / diasTrabajados;
Console.WriteLine("Pago bruto: " + pagoBruto)
Console.WriteLine("Pago por día: " + pagoPorDia);
```

2. **Con el `;` añadido.** Compila, muestra... nada: se cae antes de imprimir, porque `pagoBruto / diasTrabajados` se calcula en la línea anterior. `DivideByZeroException`. **El síntoma es la división; la causa es el dato**: `diasTrabajados` debería valer `5`.

<!--v
modo: excepcion DivideByZeroException
-->
```csharp
int horas = 40;
int tarifa = 12;
int diasTrabajados = 0;

int pagoBruto = horas + tarifa;
int pagoPorDia = pagoBruto / diasTrabajados;
Console.WriteLine("Pago bruto: " + pagoBruto);
Console.WriteLine("Pago por día: " + pagoPorDia);
```

3. **Con `diasTrabajados = 5`.** Ya no se cae, pero muestra datos equivocados: es el error lógico.

<!--v
modo: ejecuta
salida: siguiente
-->
```csharp
int horas = 40;
int tarifa = 12;
int diasTrabajados = 5;

int pagoBruto = horas + tarifa;
int pagoPorDia = pagoBruto / diasTrabajados;
Console.WriteLine("Pago bruto: " + pagoBruto);
Console.WriteLine("Pago por día: " + pagoPorDia);
```

```text
Pago bruto: 52
Pago por día: 10
```

`52` en lugar de `480`: el pago bruto es horas **por** tarifa, no horas más tarifa.

4. **Programa corregido.**

<!--v
modo: ejecuta
salida: siguiente
caso: ==> Pago bruto: 480\nPago por día: 96
-->
```csharp
int horas = 40;
int tarifa = 12;
int diasTrabajados = 5;

int pagoBruto = horas * tarifa;
int pagoPorDia = pagoBruto / diasTrabajados;
Console.WriteLine("Pago bruto: " + pagoBruto);
Console.WriteLine("Pago por día: " + pagoPorDia);
```

```text
Pago bruto: 480
Pago por día: 96
```

**Prueba con `horas = 0`:** `Pago bruto: 0`, `Pago por día: 0` (el dividendo es 0, el divisor sigue siendo 5: no hay problema).

**Reflexión sobre `diasTrabajados = 0` de verdad:** no se puede dividir entre cero. Habría que decidir **qué debe hacer el programa** si nadie trabajó ningún día (mostrar `0`, avisar de datos inválidos...) y programar una comprobación **antes** de dividir. Esa decisión es un requisito, no un detalle técnico. En la unidad 1.5 aprenderás `if`.

**Informe de hallazgos (modelo):**

| N.º | Síntoma | Hipótesis | Causa real | Corrección |
|---|---|---|---|---|
| 1 | `CS1002 ; expected` en la línea 7 | Falta un `;` | Falta un `;` | Añadir `;` |
| 2 | `DivideByZeroException` en la línea 6 | El divisor es 0 | `diasTrabajados` tenía el dato equivocado | Poner `5` |
| 3 | `Pago bruto: 52` en vez de `480` | La fórmula no multiplica | Se usó `+` en vez de `*` | Cambiar a `*` |
