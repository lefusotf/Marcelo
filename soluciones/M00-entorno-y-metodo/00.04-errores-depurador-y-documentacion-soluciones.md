## R-0.4-N1-B · Método y antipatrones

**Parte 1 · orden correcto:** (1) reproducir el fallo → (2) leer el mensaje completo → (3) formular una hipótesis → (4) comprobar la hipótesis → (5) corregir la causa → (6) verificar el caso original y casos relacionados → (7) anotar el error.

**Parte 2**

| N.º | Valoración | Por qué |
|---|---|---|
| a | **Antipatrón** | Cambios múltiples: si funciona, no sabes cuál lo arregló; si no, no sabes cuál lo rompió. |
| b | **Buena práctica** | Predecir antes de mirar convierte el depurador en una comprobación de hipótesis. |
| c | **Antipatrón** | Oculta el síntoma; la causa sigue ahí. |
| d | **Buena práctica** | Verifica no solo el caso que fallaba, sino los límites donde suelen fallar las correcciones. |
| e | **Antipatrón** | Puede ser de otra versión o incorrecta; hay que contrastar con la documentación y probar. |
| f | **Buena práctica** | El código del error es estable y la documentación oficial es la fuente primaria. |

## R-0.4-N2-A · Depurar un error lógico

**Programa original** (muestra `198` en lugar de `520`):

<!--v

-->
```csharp
int precioLista = 200;
int descuento = 15;
int unidades = 3;

int precioConDescuento = precioLista - descuento;
int subtotal = precioConDescuento + unidades;
int envio = 10;
int total = subtotal + envio;

Console.WriteLine("Total: " + total);
```

```text
Total: 198
```

**Cálculo esperado a mano:** 15 % de 200 es 30 → precio con descuento 170 → por 3 unidades, 510 → más 10 de envío, **520**.

**Tabla de valores (depurador, `F10` desde la línea 5), programa original:**

| Tras la línea | `precioConDescuento` | `subtotal` | `envio` | `total` | Esperado |
|---|---|---|---|---|---|
| `int precioConDescuento = …` | **185** | — | — | — | 170 |
| `int subtotal = …` | 185 | **188** | — | — | 510 |
| `int envio = 10;` | 185 | 188 | 10 | — | — |
| `int total = …` | 185 | 188 | 10 | **198** | 520 |

**Causas (dos, independientes):**
1. `precioLista - descuento` resta 15 como si fuera una **cantidad**, pero es un **porcentaje**: el descuento es `precioLista * descuento / 100`.
2. `precioConDescuento + unidades` **suma** unidades al precio; el subtotal debe **multiplicar**.

**Programa corregido:**

```csharp
int subtotal = precioConDescuento * unidades;
int envio = 10;
int total = subtotal + envio;

```

```text
Total: 520
```

## R-0.4-N2-B · Tres dudas, la documentación oficial

**Respuestas** (las páginas están en Microsoft Learn; sustituye `en-us` por `es-es` si quieres la traducción; las URL se encontraron mediante búsqueda y no se abrieron directamente, ver [ENLACES.md](../../recursos/ENLACES.md)):

1. **`IndexOf`:** devuelve **la posición** (empezando en 0) de la primera coincidencia, y **`-1` si no la encuentra**. `"hola".IndexOf('z')` → `-1`; `"hola".IndexOf('l')` → `2`. Documentación: [String.IndexOf](https://learn.microsoft.com/en-us/dotnet/api/system.string.indexof?view=net-10.0), sección *Returns*. Ojo: la página también explica que para búsquedas de **texto** el resultado puede depender de la comparación (cultura); aquí buscamos un solo carácter.
2. **`Math.Abs(int.MinValue)`:** lanza `OverflowException`, porque el valor absoluto de `-2147483648` (`2147483648`) **no cabe** en un `int`. Documentación: [Math.Abs](https://learn.microsoft.com/en-us/dotnet/api/system.math.abs?view=net-10.0), sección *Exceptions*.
3. **`Console.ReadLine()`:** devuelve `null` si **no hay más líneas disponibles** (por ejemplo, se cerró la entrada o se pulsó `Ctrl + Z` y Enter en Windows). Documentación: [Console.ReadLine](https://learn.microsoft.com/en-us/dotnet/api/system.console.readline?view=net-10.0), sección *Returns*. Por eso el compilador te avisa con `CS8602` si usas el resultado sin comprobar.

**Programa de comprobación de 1 y 2** *(ejecutado con SDK 10)*:

<!--v
modo: ejecuta
salida: siguiente
-->
```csharp
Console.WriteLine("hola".IndexOf('z'));
Console.WriteLine("hola".IndexOf('l'));
try { Console.WriteLine(Math.Abs(int.MinValue)); } catch (Exception e) { Console.WriteLine(e.GetType().Name + ": " + e.Message); }
```

```text
-1
2
OverflowException: Negating the minimum value of a twos complement number is invalid.
```

**Versión:** las páginas enlazadas son las de `net-10.0`. Si la tuya mostrara otra, anótalo: el comportamiento de estos tres métodos no ha cambiado, pero en general **sí puede** cambiar entre versiones.

## R-0.4-N3-A · Tres programas rotos, tres informes

### Programa A · error de compilación

- **Síntoma:** `error CS0029: Cannot implicitly convert type 'int' to 'string'` en la línea 3. No hay programa.
- **Hipótesis:** se guarda un número (`unidades * precio` es `int`) en una variable declarada como `string`.
- **Prueba:** leer el código `CS0029`; mirar los tipos: `unidades * precio` → `int`; `total` → `string`.
- **Causa:** el tipo de la variable no coincide con el valor.
- **Corrección:** `int total = unidades * precio;`.
- **Verificación:**

```csharp

int precio = 5;
string total = unidades * precio;
Console.WriteLine("Total: " + total);
```

### Programa B · error de ejecución

- **Síntoma:** `System.FormatException: The input string '12 unidades' was not in a correct format.` en la línea 2 (se caería antes de mostrar nada).
- **Hipótesis:** `int.Parse` no acepta texto con letras junto al número.
- **Prueba:** leer el mensaje: cita el texto exacto. Comprobar con otros textos.
- **Causa:** el texto contiene más que un número entero; `int.Parse` exige que el texto **sea** un número (con signo y espacios alrededor como mucho).
- **Corrección:** pasar solo el número: `"12"`. (Si algún día el texto viniera así, habría que extraer el número antes: tema de la unidad 1.13.)
- **Verificación y casos límite:**

<!--v

```csharp
int cantidad = int.Parse(cantidadTexto);

```


> **Qué quería:** guardar en un `double` el promedio de 23 entre 3 y mostrarlo con decimales.
> **Código mínimo:**

> ```
